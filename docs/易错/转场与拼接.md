# 后期模块易错记录

## 转场误差

### 0.16s 转场的累积偏移与按比例分配

**背景**：模块 B 输出的 transition_plan 中，crossfade 过渡固定为 160ms（0.16s）。
58 个 segment 之间有 57 个转场。若不做处理，每个转场会让时间轴偏移 0.16s，
最终偏移 57 × 0.16 = 9.12s。3 分钟的视频末尾偏移近 10 秒，段首帧与计划位置严重错位。

**核心公式**：

段 i 的压缩量由相邻两个过渡共同决定：

```
入过渡分担 = T_{i-1→i} × D_i / (D_{i-1} + D_i)
出过渡分担 = T_{i→i+1} × D_i / (D_i + D_{i+1})
总压缩量   = 入过渡分担 + 出过渡分担
```

段被 `setpts` 加速，speed_factor = (D_i - 总压缩量) / D_i。

**vfade 的 `duration` 取 max(T, 1/fps)**——即便 hard_cut（T=0）也会被 clamp 到 1 帧时长。
这是 ffmpeg xfade 的要求，也是下节 bug 的伏笔。

**易错点**：

1. 按比例分配后误差在各段之间来回摆动，不会无限放大
2. 段末 `tpad` 的 pad 量 = 出过渡时长 + 本段压缩量，确保 padded 后恰好覆盖原计划边界 + 过渡区
3. `setpts` 不要 inline 到 filter_complex 里——PTS 压缩后 `fps=24` 重新归一化会大量丢帧。必须**两遍预加速**（先单独 ffmpeg 生成加速文件，再拿加速后的文件做 xfade 拼接）

### pad 与 transition_duration 不一致导致 xfade 链断裂

**现象**：58 段拼接后输出仅 308 帧（预期 4631 帧），seg5 起画面冻结。

**根因**：`_resolve_xfade_transition` 对 hard_cut 返回 `("fade", 0.001)`（被 `max(0.001, 0/1000)` clamp）。
构建 filter 链时，**两处对 T 做了不同的二次 clamp**：

| 位置 | 表达式 | hard_cut 结果 |
|------|--------|---------------|
| `transition_specs`（xfade 的 `duration=`） | `max(dur, min_pad)` | **0.042** (1帧) |
| `outgoing_pad_durations`（tpad 的 `stop_duration=`） | `T_raw + compression` | **0.001 + comp** |

xfade 需要前链覆盖到 `offset + duration`。但 pad 按 `T_raw` 算，比 xfade 实际需要的 `min_pad` 少 0.041s。
第一个 hard_cut（seg4→5）处前链终点 11.293s，需要 ≥ 11.333s，缺口 0.040s，链从此断裂。

crossfade（T=0.160 ≥ min_pad）不受影响——两处 clamp 结果天然一致。

**修复**：先构建 `transition_specs`，再用其 duration 计算 pad——保证两处使用**同一个 T 值**：

```python
# 先统一 xfade transition_duration
transition_specs = []
for name, dur in transition_specs_raw:
    if dur > 0.0:
        transition_specs.append((name, max(dur, min_pad)))
    else:
        transition_specs.append((name, dur))

# pad = xfade 实际使用的 duration + 本段压缩量
outgoing_pad_durations = []
for index in range(len(spedup_paths) - 1):
    T_xfade = transition_specs[index][1]
    outgoing_pad_durations.append(T_xfade + total_compressions[index])
outgoing_pad_durations.append(0.0)
```

**易错点**：

1. `_resolve_xfade_transition` 对 hard_cut 返回 0.001 而非 0.0——`T < 0.001` 判零会漏掉
2. pad 和 xfade duration 是同一过渡的两个视角，代码中先后计算，容易不一致
3. crossfade 场景下两处天然一致，**只有 hard_cut 触发**，正常流程跑不到
4. xfade 链断裂时 ffmpeg **不报错**，只输出截断——只能从帧数骤降发现
