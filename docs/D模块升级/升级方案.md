# D模块升级方案

## 1. 与本轮 C 模块升级的关系

本轮 D 模块不直接改 Remotion 链，不直接改模板调度逻辑。

但模块 C 的升级会直接影响 D 模块的素材使用方式：

- C 输出的人物/prop 关键帧，将统一经项目自定义规则型去背节点处理后变成带透明通道的 PNG
- D 后续无论走模板链，还是保留 ToonCrafter 链，都要认识到这批素材已经更偏“贴图素材”而不是普通白底插图

---

## 2. D 模块当前仍保留并列能力

这里再次明确：

- ToonCrafter / 帧插值动作链保留
- 程序模板链保留并继续推进

它们不是废弃与回退关系，而是并列存在。

---

## 3. 本轮对 D 模块的直接启发

### 3.1 模板链更适合直接消费透明 PNG

因为 C 模块将开始输出：

- 人物透明 PNG
- prop 透明 PNG

所以 D 模块后续的模板链在素材层会更自然：

- `center` 可直接摆单个透明意象
- `grid` 可直接摆多个透明符号
- `scroll` 可直接拼透明卷轴素材或透明视觉片段

### 3.2 D 不应重复做背景抠除

既然 C 已经承担透明素材准备职责，D 后续不应再重复做：

- 白底去除
- 手工 alpha 推断
- 二次语义抠图

否则会导致职责重复。

### 3.3 D 后续更适合吃“模板请求级素材”

也就是说，D 后续模板链的输入更应是：

- 背景层
- 前景透明素材
- 模板参数
- 时间轴

而不是重新从普通插图中猜测前景区域。

---

## 4. 本轮不做的事

本轮不在 D 模块里直接落：

1. Remotion 代码接入
2. 模板请求 JSON 的正式生成
3. D 对 `asset_kind` 的消费规则扩展

这些仍然属于后续模板引擎接入阶段。

---

## 5. 本轮结论

本轮模块 D 的升级文档主要记录一个接口方向：

- C 模块开始向 D 提供更适合模板消费的透明素材
- D 后续模板链应直接建立在这些透明素材之上
- D 不再把“白底图 + 后期抠图”当成默认前提

这为后续 Remotion 模板引擎接入打下更干净的素材边界。
