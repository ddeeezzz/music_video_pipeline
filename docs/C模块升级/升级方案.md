# C模块升级方案

## 1. 本轮目标

本轮模块 C 的目标收束为四件事：

1. 修复现有人物 ComfyUI workflow 与 contract 的结构错位。
2. 将人物链路的透明层正式切换为项目自定义的规则型去背节点。
3. 新增 prop 专用 workflow，并同样走规则型去背。
4. 在代码层增加 `asset_kind`，让模块 C 能在人物与 prop 之间稳定路由。

---

## 2. 当前问题

### 2.1 scene LoRA 绑定错位

当前 `module_c_start/end.contract.json` 中声明了：

- `scene_lora_* -> node 4`

但旧的 workflow JSON 中没有 `4` 号节点，导致 contract 与 workflow 结构不一致。

这个问题必须先修，不然后续无论补什么后处理链都不稳。

### 2.2 语义抠图路线不再作为正式方案

模块 C 一开始尝试过：

```text
ImageScale -> ImageColorToMask -> JoinImageWithAlpha -> SaveImage
```

这条链对“几何符号、极简线稿、纯背景分离素材”有一定可用性，但不适合当人物正式方案，原因很直接：

1. 黑白人物内部本来就可能有大面积纯白区域。
2. 直接按白色扣背景会把主体内部掏空。
3. AI 线稿不保证完全闭合，不能把连通域算法当成稳定前提。

因此本轮路线继续收束为：

- `character -> 自定义规则型去背节点`
- `prop -> 自定义规则型去背节点`

### 2.3 模板层需要的是“稳定透明素材”

后续模板层、ToonCrafter 链与其它 D 模块消费方要拿到的，不是普通白底图，而是：

- 带透明通道的前景素材 PNG

因此模块 C 的职责不是“尽量生成白底图”，而是：

- 直接把可复用透明素材准备好

---

## 3. 正式依赖路线

### 3.1 后处理统一改为项目自定义节点

本轮将人物与 prop 的透明层正式统一到项目自定义的规则型去背节点。

当前 workflow 采用的节点链为：

```text
ImageScale -> MVPL: ExtractComicAlpha -> SaveImage
```

### 3.2 当前选型

当前 workflow 设计按项目自定义节点 `MVPL: ExtractComicAlpha` 落地。

这个节点只保留一个图像输入与一个图像输出，内部固定执行：

1. 黑线阈值提取。
2. 轻微闭运算与膨胀修补断线。
3. 从外部背景执行 Flood Fill。
4. 将背景设为 Alpha=0，并把结果回贴到原图。

原因很简单：

1. 本项目大量素材是白底漫画图、黑白线稿或视觉符号。
2. 语义抠图模型会把主体内部白色区域误判成背景。
3. 规则型算法虽然朴素，但对这类素材更稳定、可控、可复现。

### 3.3 当前代码与环境的关系

这里要明确一件事：

- 本轮已经把文档和 workflow 路线修正成项目自定义规则型去背
- 但当前本机若尚未安装对应 custom node，真实 ComfyUI 执行仍然不会成功

也就是说，这轮改的是：

- 正式技术路线
- workflow 结构
- 模块接口方向

运行前仍需补齐 ComfyUI 依赖。

---

## 4. 人物 workflow 的调整

### 4.1 结构修正

人物 `start/end` workflow 统一为：

```text
Checkpoint
 -> Scene LoRA
 -> Character LoRA
 -> Prompt
 -> KSampler
 -> VAEDecode
 -> Upscale
 -> ImageScale
 -> MVPL: ExtractComicAlpha
 -> SaveImage
```

### 4.2 目的

- 修正 scene LoRA 节点错位
- 保留人物 LoRA
- 让人物链路正式转入规则型透明层提取
- 直接输出带 alpha 的透明 PNG

---

## 5. prop workflow 的新增

### 5.1 prop 的定位

prop 指：

- 非人物视觉符号
- 道具
- 静物
- 模板拼接用的象征性物件

### 5.2 prop workflow 设计

prop `start/end` workflow 统一为：

```text
Checkpoint
 -> Scene LoRA
 -> Prompt
 -> KSampler
 -> VAEDecode
 -> Upscale
 -> ImageScale
 -> MVPL: ExtractComicAlpha
 -> SaveImage
```

与人物链的核心区别仍然是：

- 去掉 `Character LoRA`

### 5.3 为什么 prop 也走自定义规则型去背

这里不再保留“prop 先走 color key”的正式路线，原因是：

1. prop 后续会越来越多样，不会永远是纯线框几何图。
2. 视觉意象、物件、符号的内部也可能有白色主体区域。
3. 模板层更需要“统一输入规范”，不希望上游混用两种透明层逻辑。

因此当前正式口径就是：

- `character -> 自定义规则型去背节点`
- `prop -> 自定义规则型去背节点`

---

## 6. 代码层设计

### 6.1 新增 `asset_kind`

模块 C 本轮新增：

```text
asset_kind = character | prop
```

默认值为：

```text
character
```

### 6.2 `ComfyUIFrameGenerator` 内部行为

生成器内部根据 `asset_kind` 选择对应 contract：

- `character -> module_c_start/end.contract.json`
- `prop -> module_c_prop_start/end.contract.json`

两条链都走同一个规则型去背节点，区别只在于：

- 人物链保留人物 LoRA
- prop 链不加载人物 LoRA

### 6.3 本轮不新增第二套生成器类

本轮仍不拆：

- `CharacterFrameGenerator`
- `PropFrameGenerator`

原因不复杂：

1. 当前主要差异集中在 contract 与 LoRA 绑定。
2. 生成与拷贝逻辑高度重合。
3. 先把工作流路线收拢，比过早拆类更重要。

---

## 7. 输出产物约定

本轮模块 C 输出的 `frame_001.png`、`frame_001_end.png` 等文件，应默认视为：

- 已经过规则型去背节点处理的透明 PNG

这意味着下游默认可以直接把它们当成：

- 前景层素材
- 模板贴图素材
- ToonCrafter 首尾帧前景资产

而不应再把它们视为“还要自己去白底”的普通插图。

---

## 8. 依赖补齐要求

由于当前 workflow 已正式转向项目自定义节点，实际运行前需要补齐以下依赖：

1. 安装项目自定义 ComfyUI 节点目录 `mvpl_comic_alpha`。
2. 确认 ComfyUI 能识别：
   - `MVPL: ExtractComicAlpha`

这个节点不依赖额外模型文件，依赖仅为本机已有的 `opencv-contrib-python`、`numpy`、`PIL` 与 `torch`。

---

## 9. 本轮结论

本轮模块 C 的正式方向已经修正并明确：

1. 先修 workflow / contract 错位。
2. 人物透明层正式切到项目自定义规则型去背节点。
3. prop 透明层也统一切到项目自定义规则型去背节点。
4. 用 `asset_kind` 统一调度人物与非人物素材链。

这样做的核心收益不是“多一个插件”，而是把模块 C 向下游提供的素材标准真正统一成：

- 可直接消费的透明前景资产。
